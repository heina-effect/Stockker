# UI/UX Validation & Improvement Notes (Phase 3)

본 문서는 브라우저 검증(Phase 3) 관찰 결과를 바탕으로 프론트엔드 UI의 사용성 및 사용자 경험에 대한 평가와 개선안을 정리합니다.

## 1. UI 일관성 및 가독성 평가

### 긍정적 지점
- **Source Badge 가독성**: `MOCK` 배지가 주황색 계열로 확연하게 구분되며, `Live`로 전환 시의 초록색 테마와 명확한 대비를 이뤄 시스템의 현재 데이터 출처를 직관적으로 파악할 수 있습니다.
- **동기화 상태**: Watchlist의 현재가와 Orderbook 상단의 체결 대기 호가, Price Chart의 최근접 y점 값이 완벽한 타이밍에 같이 움직임으로써 이질감을 줄입니다.

### 아쉬운 지점 (사용자 혼동 유발 가능 부분)
- **차트 X축 표기 방식**: 차트의 X축 틱(tick) 텍스트 대비 여백이 조금 좁아 수 초간 여러 틱이 폭증할 경우 라벨이 겹칠 우려가 있습니다(`interval="preserveStartEnd"`를 사용 중이나 틱 간격 보정 권장).
- **에러 모달 부재**: 만약 KIS 서버의 일시적 장애로 Mock Fallback 전환이 일어났다면, 사용자는 "왜 갑자기 모의 환경인가요?"라고 혼란을 겪을 수 있습니다. 시스템 토스트 팝업이나 Status Bar에 에러 원인 표기가 필요합니다.

## 2. 프론트엔드 개선 제안

1. **차트 애니메이션 트위닝(Tweening)**
   - 가격이 갱신될 때 선이 딱딱하게 끊기기보다는 이전 가격과의 선형 보간(Linear interpolation) 애니메이션을 조금 더 추가해 부드러운 움직임을 연출하면 시각적 만족도가 극대화됩니다.
2. **호가창 잔량 바(Depth Bar) 시각화**
   - 현재 숫자로만 잔량(Size)이 표시되나, 총 호가 잔량 대비 비율을 배경 Bar(차트 형식)로 칠해준다면 훨씬 더 '트레이딩 플랫폼' 다운 디자인 연출이 가능합니다.
3. **SSR Mock Hydration 지원**
   - 앞서 리포트된 바와 같이, 환경 변수에 토큰이 없다면 `LiveMarketProvider` 클라이언트 마운트 전에 서버 컴포넌트 레벨에서 미리 Mock 데이터를 채워 깜박임(Flicker)을 최소화하는 방향으로 구조를 제안합니다.
