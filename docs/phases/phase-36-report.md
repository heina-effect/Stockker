# Phase 36 Report — 오버나이트 스크리닝 알고리즘 고도화 및 36audit 핫픽스

## 완료 요약

오버나이트 스크리닝 리포트 알고리즘의 세부 정합성과 시스템 안정성을 비약적으로 높이기 위해 **알고리즘 감사 지침(36audit)**을 수렴하고, 관련된 9가지 버그 핫픽스 및 기능 개선 작업을 성공적으로 마무리한 데 이어, 사용자의 피드백을 반영하여 **유동성 회전율(vol_tnrt) 기준 도입, 위험 필터 코드값 확정(mrkt_warn_cls_code 등), 외국인 순매수 여력 규칙 자동화** 작업을 최종 완료하였다.

이번 개선을 통해 스크리닝 리포트 상세 페이지의 종목 카드 가격 노출에서 불필요한 달러 기호를 삭제하고 원화 단위만 표시하여 시인성을 높였으며, '메리츠제2호스팩'과 같은 스팩주(SPAC)가 분석 후보 및 제외 종목을 포함한 모든 스크리닝 노출 항목에서 원천적으로 필터링되도록 정밀 정규식을 확장하여 스크리닝 정합성을 한 단계 더 끌어올렸다. 

더불어, 유동성 기준에 고정 거래대금 컷(100억) 대신 거래량 회전율(`vol_tnrt` >= 5.0%)과 최소 거래대금 안전장치(10억)를 도입해 소형주가 과도하게 배제되는 한계를 완벽히 극복하였고, 주식현재가 시세 API의 원시 출력 필드를 직접 활용하여 투자경고, 거래정지, 단기과열 등의 위험 필터 코드값을 확실하게 매핑하였다. 또한 외국인 순매수 여력을 판정하여 익일 매수 여력 부족 우려 플래그(`foreignBuyLimit`)를 자동화하는 등의 추가 요건 역시 완벽히 만족시켰다.

## 주요 변경 및 개선 사항

### 1. 알고리즘 정밀 교정 및 위험 필터 확정 (2차 개선)
- **위험종목 필터 기준 확정 및 교체**: 기존의 `iscd_stat_cls_code` 기반 추측성 방식을 전면 폐기하고, KIS 현재가 시세 API의 원시 출력 필드를 활용하여 투자주의/경고/위험, 투자유의, 거래정지, 정리매매, 단기과열 종목을 정밀하고 명확한 기준에 의해 차단하도록 구현했습니다:
  - `mrkt_warn_cls_code !== "00"` (투자주의/경고/위험 제외)
  - `invt_caful_yn === "Y"` (투자유의 제외)
  - `temp_stop_yn === "Y"` (거래정지 제외)
  - `sltr_yn === "Y"` (정리매매 제외)
  - `short_over_yn === "Y"` (단기과열 제외 및 공격형 이하 강등)
- **거래대금 고정 컷 폐기 및 회전율(vol_tnrt) 도입**: 기존 100억 고정 컷으로 소형주가 탈락하는 문제를 수정하기 위해 당일 거래량 회전율 `vol_tnrt >= 5.0%`를 1차 기준으로 도입하고, 초저유동성 방지를 위한 느슨한 안전장치로 누적 거래대금 10억 원 이상 컷만 적용해 후보군 대상을 확대했습니다.
- **외국인 순매수 여력 규칙 자동화**: 당일 외국인순매수수량(`frgn_ntby_qty`)이 상장주식수 대비 0.5% 이상이거나 당일 거래량 대비 15% 이상일 때 `"익일 추가매수 여력 적음"` 플래그(`foreignBuyLimit: true`) 및 관련 분석 이유를 생성해 결과 종목에 포함시켰습니다.
- **신선도 거래량/변동성 수렴 판정 버그 해결**: 장대양봉 발생일 다음날부터 오늘 직전까지로 조정 기간을 한정하여 수렴 판정 정합성을 교정했습니다.
- **거래량 200% 비교 분모 오류 교정**: 오늘 거래량을 분모에서 차단하고 오늘 제외 최근 20일을 기준으로 평균 거래량을 계산하도록 수정했습니다.
- **거시 필터 정상화 및 `weightSuggestion` 추가**: 코스닥 역배열 시에도 정석 종목이 버킷에서 빠지지 않도록 유지하고 각 종목에 `weightSuggestion` 필드(0.5 또는 1.0)를 제공해 UI 상에 `비중 50% 축소 제안` 배지가 노출되도록 개선하였습니다.

### 2. UI 달러 표시 제거 및 스팩주(SPAC) 원천 필터링
- **달러 표시($) 제거**: 오버나이트 상세 페이지(`src/app/overnight/page.tsx`)의 종목 카드 가격 렌더링에서 달러 기호 아이콘을 제거하고 원화 단위(`원`)만 깔끔하게 노출하도록 UI를 수정했습니다.
- **스팩주 원천 필터링**: API 내 `etfRegex`에 `spac` 및 `스팩` 키워드를 추가하여, 이름에 해당 명칭을 포함하는 모든 스팩주가 분석 대상 후보군 및 제외 종목 리스트를 포함한 전체 스크리닝 범위에서 원천 차단되도록 구현했습니다.

### 3. KIS API Rate Limit 전역 차단 및 예외 대처 (Stability)
- **글로벌 KIS API 요청 큐 도입**: `auth.ts`에 글로벌 요청 큐(`KisRequestQueue`)를 도입해 Next.js HMR 환경을 고려한 `globalThis` 싱글톤 패턴과 510ms의 대기 시간을 적용하여 모든 KIS API 호출 속도를 전역적으로 제어함으로써 모의투자(TPS 2) 제한을 원천 차단했습니다.
- **백엔드 Graceful Break 설계**: KIS API 호출 중 예기치 않게 429(Rate Limit) 에러 발생 시 백엔드 루프가 500 에러를 뿜으며 죽지 않고, 그 시점까지 완료된 정상 분석 데이터만 모아 사용자에게 리포트를 서비스하는 예외 대처 설계를 도입하여 백엔드 크래시를 완벽 방어했습니다.

### 4. 후보군 확대 및 ETF 정교화 (Quality)
- **후보군 30종목 풀 확대**: KIS 거래량 및 거래대금순 상위 종목 조회를 병합하여 중복 제거된 50~60개 풀을 확보하고, 당일 상승률 3% 이상 및 누적 거래대금 10억 원 이상, 회전율 5% 이상인 주식을 우선으로 상위 30종목 후보군으로 확대했습니다.
- **ETF/ETN 오탐 정밀 차단**: `type` 및 `market` 마스터 정보를 최우선 신뢰하고 접두어 정규식을 적용해 일반 주식명 오탐을 완벽히 방지했습니다.
- **디버그 모드 mock fallback 차단**: `?debug=true` 요청 시 mock 데이터 Fallback을 차단하여 실제 에러가 즉시 전파되도록 조치했습니다.

## 보존한 가드레일 (Non-Negotiables)

- **인트라데이 숨김**: 당일의 실시간 1분봉 차트는 제공하지 않는 정책을 준수합니다.
- **단일 Fetch 홈 구조**: 기존 홈 카드의 단일 fetch 구조와 부하 방지 규칙을 깨지 않기 위해 오버나이트 카드는 독자적인 `/api/screening/overnight` API를 호출하도록 설계했습니다.
- **추천 disclaimer 규칙**: 스크리닝 화면 하단에 투자 권유가 아니며 판단과 책임은 투자자 본인에게 있다는 면책 조항(Disclaimer)을 명확하게 명시하였습니다.
