# Phase 10 Audit: 당일 차트 정합성 및 데이터 무결성 분석

## 1. 개요
본 감사는 Stockker 시스템에서 반복적으로 발생했던 "당일 차트(Intraday)의 시각적 붕괴" 및 "데이터 스케일(Scale) 불일치" 문제의 기술적 원인을 규명하고, 이를 근본적으로 해결하기 위한 아키텍처적 조치를 기록합니다.

## 2. 근본 원인 분석 (Root Cause Analysis)

### 2.1. 프론트엔드 난수 생성기 (`fakeHistory`) 의존성
- **결함**: 기존 `LiveMarketProvider` 부트스트랩 단계에서 과거 분봉 데이터를 API에서 가져오지 않고, `Math.random()`을 이용해 49개의 1분 단위 더미 캔들(`fakeHistory`)을 강제로 생성하여 렌더링에 사용했습니다.
- **영향**: 실시간 데이터와 무작위 난수가 하나의 배열로 병합되면서 Y축의 상한/하한이 난수에 의해 지배되었고, 이로 인해 실제 주가 흐름이 일직선으로 보이거나 차트가 붕괴되는 현상이 발생했습니다.

### 2.2. 하드코딩된 폴백(Fallback) 가격 정책
- **결함**: KIS API 호출 실패 시 `bootstrap` 라우터에서 `70000`원이라는 하드코딩된 가격을 반환했습니다.
- **영향**: SK하이닉스(110만 원대)와 같이 가격대가 높은 종목에서 API 지연이 발생할 경우, 캔들 하나가 7만 원으로 찍히게 되어 Y축이 0~110만 원 전체를 덮게 되며 차트 눈금이 무너졌습니다.

### 2.3. AI 리포트 데이터 소스의 비실재성
- **결함**: 리서치 리포트의 "핵심 이슈" 섹션이 실제 뉴스 API가 아닌 정적 Mock 데이터에 의존하고 있었습니다.

## 3. 해결 설계 (Solution Design)

### 3.1. API 기반 OHLC 백필 (Backfill) 도입
- 프론트엔드 자체 생성 난수를 전면 제거하고, `/api/stocks/[symbol]/ohlc` 엔드포인트를 통해 KIS의 실제 당일/일봉 시계열을 가져오도록 변경했습니다.

### 3.2. 데이터 무결성 가드레일 (Scaling Guard)
- 실시간 가격 유입 시, 과거 데이터(Last 100 days/ticks)의 종가와 비교하여 50% 이상의 극단적인 괴리가 발생하는 경우(에러 데이터로 판단) 해당 틱을 차트 렌더링에서 제외하는 보호 로직을 추가했습니다.

### 3.3. KIS 뉴스 API 통합
- `FHKST01012200` 트랜잭션을 통해 실제 시장 뉴스를 가져와 AI 리포트에 공급함으로써 "Real AI Report Sources" 요건을 충족했습니다.

## 4. 회귀 방지 (Regression Guardrails)
- **단위 테스트**: `chart-utils.test.ts`를 통해 집계 로직의 정확성을 상시 검증합니다.
- **지속적 검증**: `npm run validate:full` 명령어를 통해 API 라우터와 UI 컴포넌트의 타입 안정성을 체크합니다.
